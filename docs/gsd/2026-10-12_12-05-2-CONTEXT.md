# Contexto da Fase 2: Gerador de Scripts Progress ABL (.p) com Log de Erros

## Decisões

_Estas são decisões BLOQUEADAS._ O Planejador DEVE respeitá-las.

- O gerador DEVE suportar dois modos de geração do script `.p`:
  1. **Modo Puro:** Gera apenas as linhas `COMPILE <programa> SAVE.` para cada programa compilável selecionado.
  2. **Modo com Log de Erros (`NO-ERROR`):** Gera um script `.p` estruturado que compila com `COMPILE <programa> SAVE NO-ERROR.` para não travar o Procedure Editor em caso de erro de compilação.
- No **Modo com Log de Erros**:
  - O arquivo `.log` DEVE ser salvo **sempre no mesmo diretório do próprio script `.p`** (ex: se o script for salvo em `C:\temp\compila-es-teste.p` ou executado de uma pasta, o log será gravado na mesma pasta do script como `compile-errors.log` ou `<nome-do-script>.log`).
  - O arquivo `.log` DEVE registrar **exclusivamente os programas que falharem na compilação (`COMPILER:ERROR`)**, ignorando completamente os programas que compilaram com sucesso.
  - **Apenas se houver erros** ao final da execução do script (`i-tot-erros > 0`), o script `.p` DEVE exibir um `MESSAGE` informando que ocorreram erros na compilação e mostrando o caminho completo do arquivo `.log` gerado.
- O comando `COMPILE` DEVE usar sempre `COMPILE <programa> SAVE.` / `COMPILE <programa> SAVE NO-ERROR.` (sem cláusula `SAVE INTO`).
- O gerador DEVE permitir escolher entre formatar `<programa>` com **Caminho Relativo à raiz pesquisada (padrão PROPATH)** ou **Caminho Absoluto**.
- Apenas os programas marcados pelo usuário (`SelectedForCompile == true` e `IsCompilable == true`) DEVEM entrar no script `.p`.

## Ideias Adiadas

_Estas coisas explicitamente NÃO acontecerão nesta fase._ O Planejador NÃO DEVE incluir tarefas para elas.

- Sem cláusula `SAVE INTO <diretório>`.
- Sem logar programas compilados com sucesso `[OK]` no arquivo `.log`.
- Construção da tela gráfica Windows Forms (ficará na Fase 3).

## Discrição da IA

_Áreas onde o usuário não forneceu preferência e autorizou a IA a fazer escolhas técnicas._

- Uso de procedure interna auxiliar no `.p` gerado (ex: `RUN pi-compilar (INPUT "<programa>").`) para evitar repetição de blocos `IF COMPILER:ERROR THEN DO:` em scripts com dezenas ou centenas de programas, mantendo o `.p` gerado extremamente limpo, legível e compacto!
- Determinação dinâmica do diretório do próprio script `.p` no Progress ABL usando `FILE-INFO:FILE-NAME = THIS-PROCEDURE:FILE-NAME` (com fallback para o caminho onde o `.p` foi exportado ou diretório corrente `.`), garantindo que o `.log` sempre caia exatamente na mesma pasta do script `.p`.
- Inclusão de linha/coluna do erro (`COMPILER:ERROR-ROW` e `COMPILER:ERROR-COLUMN`) e todas as mensagens de `ERROR-STATUS:GET-MESSAGE(i-msg)` no arquivo `.log` para cada programa que falhar.
