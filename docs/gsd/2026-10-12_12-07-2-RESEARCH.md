# Pesquisa Técnica da Fase 2: Gerador de Scripts Progress ABL (.p) com Log de Erros

## 1. Tratamento de Erros de Compilação no Progress 4GL / ABL
- Quando o comando `COMPILE <programa> SAVE.` encontra um erro de sintaxe, tabela inexistente ou include ausente sem a cláusula `NO-ERROR`, o Progress Procedure Editor / AppBuilder interrompe o processamento com um alerta modal de erro na tela.
- Com `COMPILE VALUE(p-programa) SAVE NO-ERROR.`, a compilação não trava a sessão. Em seguida:
  - `COMPILER:ERROR` retorna `TRUE` se houve falha de compilação.
  - `COMPILER:ERROR-ROW` e `COMPILER:ERROR-COLUMN` indicam a linha e coluna onde o erro ocorreu.
  - `ERROR-STATUS:NUM-MESSAGES` retorna o total de mensagens de erro geradas, e `ERROR-STATUS:GET-MESSAGE(i-msg)` + `ERROR-STATUS:GET-NUMBER(i-msg)` retornam a descrição e o código Progress de cada erro.

## 2. Resolução do Diretório do Próprio Script `.p` para o Arquivo `.log`
- O requisito estabelece que o `.log` deve ser salvo **sempre no mesmo diretório do script `.p`** e conter **exclusivamente os programas que falharem na compilação (`COMPILER:ERROR`)**.
- Em Progress ABL:
  - Podemos determinar o caminho completo do `.p` em execução usando `FILE-INFO:FILE-NAME = THIS-PROCEDURE:FILE-NAME` e `FILE-INFO:FULL-PATHNAME`.
  - Caso o usuário cole o código diretamente em uma janela sem arquivo salvo (`FILE-INFO:FULL-PATHNAME = ?`), usamos como fallback o diretório onde o script foi gerado (ou `SESSION:TEMP-DIRECTORY`).
  - Substituindo a extensão `.p` por `.log` (ou concatenando `compile-errors.log` no mesmo diretório), garantimos que o `.log` sempre fique ao lado do script `.p`.
- Para que o arquivo `.log` só contenha erros (e nem seja populado com sucessos):
  - Antes do loop de compilação, se um `.log` antigo de execução anterior existir no mesmo caminho, executamos `OS-DELETE VALUE(c-arq-log) NO-ERROR.`.
  - Na procedure interna `pi-compilar`, somente dentro do bloco `IF COMPILER:ERROR THEN DO:`, abrimos `OUTPUT STREAM s-log TO VALUE(c-arq-log) APPEND UNBUFFERED.` e gravamos os detalhes do programa que falhou, fechando com `OUTPUT STREAM s-log CLOSE.`.
  - Ao final do script, verificamos `IF i-tot-erros > 0 THEN MESSAGE ... VIEW-AS ALERT-BOX ERROR BUTTONS OK.` informando a quantidade de programas com erro e o caminho exato de `c-arq-log`.

## 3. Estrutura Limpa do Script `.p` Gerado
- **Modo Puro (`CompileScriptMode.Simple`):**
  ```progress
  COMPILE esp/es0001.p SAVE.
  COMPILE esp/es0002.w SAVE.
  ```
- **Modo com Log de Erros (`CompileScriptMode.WithErrorLog`):**
  Usa chamadas enxutas `RUN pi-compilar (INPUT "esp/es0001.p").` para cada programa selecionado e define `PROCEDURE pi-compilar:` no final do arquivo. Isso mantém o script `.p` organizado mesmo quando há centenas de programas para compilar.
