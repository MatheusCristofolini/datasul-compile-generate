# Manifesto do Projeto: Datasul Search & Compile Script Generator

## 1. Nome e Identidade do Projeto
- **Nome:** Datasul Search & Compile Generator (`DatasulCompileGen.exe`)
- **Categoria:** Utilitário Desktop Portátil para Desenvolvedores Progress 4GL / ABL (TOTVS Datasul)
- **Formato de Entrega:** Executável único portátil (`.exe`) nativo do Windows, sem necessidade de instalador ou dependências externas.

## 2. Proposta de Valor Central
Quando tabelas ou objetos do dicionário de dados Progress Datasul sofrem alterações (ex: tabela `es-teste-123`), todos os programas que referenciam essa tabela — seja diretamente em arquivos compiláveis (`.p`, `.w`) ou indiretamente por meio de arquivos de include (`.i`) — precisam ser recompilados para atualizar o CRC/r-code.

Esta ferramenta unifica **busca rápida de código (estilo VS Code)** com a **geração automatizada de scripts de compilação Progress (`.p`) resilientes a erros**, eliminando o trabalho manual de localizar referências, rastrear includes e montar scripts `COMPILE <programa> SAVE.` com log de erros.

## 3. Público-Alvo e Objetivos
- **Público-Alvo:** Desenvolvedores, analistas e administradores de ambientes Progress OpenEdge / TOTVS Datasul.
- **Objetivos Principais:**
  1. Varredura ultrarrápida em diretórios de fontes Progress (`.p`, `.w`, `.i`, `.cls`, etc.) buscando termos exatos, múltiplos termos ou case-insensitive.
  2. Visualização clara estilo VS Code: árvore de arquivos encontrados, contagem de ocorrências, linhas onde o termo aparece e painel de visualização (preview) do código com destaque da linha.
  3. Resolução reversa automática de Includes (`.i`): se o termo for encontrado dentro de um arquivo `.i`, localizar automaticamente quais programas compiláveis (`.p`, `.w`) incluem esse `.i` (direta ou recursivamente) para que entrem na lista de compilação.
  4. Geração flexível do script `.p` de compilação:
     - Seleção individual (checkboxes) dos programas que entrarão no script.
     - Escolha entre **Caminho Relativo à raiz/PROPATH** (ex: `esp/es0001.p`) ou **Caminho Absoluto**.
     - Escolha entre **Modo Simples** (`COMPILE <programa> SAVE.`) ou **Modo com Log de Erros Não-Bloqueante** (`COMPILE <programa> SAVE NO-ERROR.` + captura de `COMPILER:ERROR` e gravação de mensagens `ERROR-STATUS` em arquivo `.log` para que o Procedure Editor não trave em popups de erro).

## 4. Stack Tecnológica e Restrições
- **Linguagem & Runtime:** C# compilado nativamente para `.NET Framework 4.8` (presente nativamente em 100% das instalações Windows 10/11 via `csc.exe`, garantindo um `.exe` portátil leve, instantâneo e sem necessidade de instalar runtimes adicionais).
- **Interface Gráfica:** Windows Forms moderno (Dark/Light Theme inspirado no VS Code, layout com `SplitContainer`, `TreeView`/`ListView` com checkboxes, preview de código e barra de status com progresso assíncrono).
- **Restrições Inegociáveis:**
  - Deve ser um único arquivo `.exe` portátil.
  - A busca não pode congelar a interface gráfica (execução assíncrona com cancelamento e barra de progresso).
  - O script `.p` com log de erros nunca deve deixar o Progress travar em tela de erro durante a compilação em lote.
